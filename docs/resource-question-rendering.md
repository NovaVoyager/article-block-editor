# 资源问题：独立渲染器实现说明 v1

本文可直接交给独立渲染器项目的开发者或 AI。适用于 Vue、React 及其他框架，说明问题快照展示、选项跳转、后续内容隐藏与 revealKey 解锁的执行逻辑。

## 1. 实现范围与职责

当前编辑器已实现：选择外部资源并保存快照、为选项绑定文章段落、配置隐藏开关与解锁标识、导出 JSON 和最新协议。编辑器及其只读预览始终显示全文，不执行业务隐藏。

独立渲染器需要实现本文的展示、事件、可见内容计算和滚动逻辑；宿主项目负责判断何时允许解锁。本包没有提供 `ArticleRenderer`。下文的 `revealedKeys` 属性和 `onOptionSelect` 回调是**待实现的接口建议**，不是现有编辑器接口。

实施时同时提供编辑器“下载协议”导出的 `article-content-protocol-latest.json`，以其中的 `documentSchema` 和 `resourceQuestionRules` 为协议依据。只读渲染不要求依赖 Vue 编辑器包，也不应复制编辑器的 NodeView 作为最终渲染器。

## 2. 数据结构与标识

### 2.1 完整文档示例

```json
{
  "type": "doc",
  "content": [
    {
      "type": "resourceQuestion",
      "attrs": {
        "id": "question-1",
        "resourceId": "resource-123",
        "title": "你的入睡时间是多久？",
        "description": "选择一个选项查看文章中的对应内容",
        "image": { "src": "/images/sleep-question.png", "alt": "睡眠问题配图", "width": 960, "height": 360 },
        "options": [
          { "id": "option-a", "label": "5 分钟以内", "targetAnchorId": "option-a" },
          { "id": "option-b", "label": "其他情况" }
        ],
        "hideFollowing": true,
        "revealKey": "report-access"
      }
    },
    {
      "type": "paragraph",
      "attrs": { "anchorId": "option-a" },
      "content": [{ "type": "text", "text": "这是选项 A 对应的文章段落。" }]
    }
  ]
}
```

`resourceQuestion` 仅允许作为 `doc.content` 的直接子节点，不可放进引用、列表或表格。正文和标题的 `anchorId` 可选，旧文档不必补充锚点或资源问题。

问题名、描述和答案选项直接读取 `attrs` 中保存的快照。**不根据 resourceId 请求资源接口，也不使用外部实时数据替换快照。** 外部问题修改后，已保存文章不会自动变化；需在编辑器重新选择资源并保存文章。

### 2.2 不要混淆这些 ID

| 字段 | 用途 | 唯一性范围 |
| --- | --- | --- |
| `attrs.resourceId` | 标识所选外部资源的来源 | 一篇文章可以多次引用同一资源 |
| `attrs.id` | 标识文章中的这个问题模块实例 | 同一篇文章内唯一 |
| `options[].id` | 外部提供的稳定选项 ID，不以文案或下标代替 | 同一问题内唯一 |
| `options[].targetAnchorId` | 该选项绑定的目标段落标识，可不配置 | 可以与其他选项指向同一目标 |
| 段落/标题的 `attrs.anchorId` | 用于精确定位段落，与 targetAnchorId 匹配 | 同一篇文章内唯一 |
| `attrs.revealKey` | 标识该问题之后内容的解锁条件 | 同一篇文章内唯一，不同文章可复用 |

`revealKey` 不是段落 ID、选项 ID、密码或请求资源接口的参数。一个问题下的不同选项共享该问题的 revealKey，但可以跳转到不同段落。

新编辑器绑定规则为 `options[].id = options[].targetAnchorId = 目标段落.attrs.anchorId`。例如选项 ID 为 `AUV6gOa9`，绑定或显式转换后，段落就渲染为 `data-anchor-id="AUV6gOa9"`，可以在当前文章实例内直接用该选项 ID 定位。三个字段职责仍不同，协议保留 targetAnchorId，不把历史文章中的不相等判为无效。

旧文章加载时不会自动迁移，UUID 格式锚点仍有效；需要在编辑器重新绑定或点击“使用选项 ID 作为锚点”，保存并重新加载 JSON 才会变成新值。为了兼容历史文章，渲染器的通用定位逻辑仍优先使用选项的 targetAnchorId；未绑定选项不应仅因为有 option.id 就擅自跳转。上述数据属性也不是 HTML id，不能直接使用 document.getElementById。

锚点在文章内唯一：同 ID 的选项可以共享一个目标，不同段落不能同时占用该 ID。若新绑定会覆盖不同选项的现有目标或改变其他问题的跳转，编辑器会拒绝并提示处理冲突；这不会使旧版多选项共用段落的文章失效。

### 2.3 可选的标题上方图片

资源问题新增可选 `attrs.image: { src, alt?, title?, width?, height? }`。它是随文章保存的图片快照，可能来自资源数据，也可能由编辑器内单独上传替换；渲染器不需要区分来源或请求资源 API，只加载保存的图片地址。

渲染顺序为：图片（若有）→ 问题名 → 问题描述 → 答案选项。省略 image 时不创建图片节点、不预留图片间距，完全兼容旧文章。没有图片时导出 JSON 不保存 image 字段，不使用空 src 或 null 表示图片。

`src` 必填，`alt`/`title` 为可选字符串，`width`/`height` 为可选的 1～10000 整数。绑定 img 的 src、alt、title 及可选尺寸；图片最大宽度为容器宽度，高度等比例缩放，例如 `display: block; max-width: 100%; height: auto; margin: 0 auto 18px`。有尺寸时应预留等比例空间以减少段落跳转后的布局偏移，不用固定大高度或 object-fit: cover 裁切图片。图片加载失败应提供合理替代提示，不影响问题选项与解锁逻辑。

同一问题只能保存一张顶部图片。图片不带新的跳转或解锁标识，image 的变更也不影响原有 revealKey 和 targetAnchorId。若渲染器按节点属性白名单读取数据，请同步允许 image 及其字段；按下载协议里的 `resourceQuestionImage` 定义校验，不将图片属性直接作为任意 HTML 注入。

## 3. revealKey 的执行逻辑

### 3.1 标识何时产生，保存在哪里？

当前编辑器插入一个新问题模块时，生成随机实例 ID，并默认将同一字符串作为 revealKey，例如 `question-abc`。两者职责不同，之后可以单独修改 revealKey。

- 标识保存在问题节点的 `attrs.revealKey` 中，随文章 JSON 一起保存。
- 重新打开文章或重新渲染不会重新生成标识。
- 复制问题模块会生成新的实例 ID 和 revealKey，避免同篇文章内冲突。
- 渲染器直接读取保存值，不重新生成，也不要假设 revealKey 永远等于问题实例 ID。

因此，它不是“每次渲染生成一个、前端需要额外查询”的值，也不是整篇文章只能有一个的文章 ID。

### 3.2 前端不预先知道随机值，怎么解锁？

让渲染器在用户点击选项时，把当前问题的 revealKey 一起返回给宿主即可。宿主不需要硬编码随机值或单独请求接口获取它。

建议渲染器提供受控输入：

| 接口 | 职责 |
| --- | --- |
| `document` | 原始完整 ProseMirror JSON |
| `revealedKeys: string[]` | 宿主当前允许解锁的标识列表，默认 `[]` |
| `onOptionSelect(event)` | 点击选项时通知宿主，具体事件命名按框架约定 |

建议事件结构（以下类型属于渲染器项目的接口设计，不是编辑器包的导出类型）：

```ts
interface ResourceQuestionSelectEvent {
  questionId: string
  resourceId: string
  optionId: string
  revealKey: string
  targetAnchorId?: string
}
```

以第 2 节的 JSON 为例，完整执行顺序是：

1. 宿主把文章 JSON 和 `revealedKeys = []` 传给渲染器。
2. 渲染器显示问题；因为 hideFollowing 为 true 且 `report-access` 不在列表中，问题后的段落暂不渲染。
3. 用户点击 `option-a`，渲染器发出事件，携带 `questionId = question-1`、`resourceId = resource-123`、`optionId = option-a`、`revealKey = report-access` 和 `targetAnchorId = option-a`。
4. 宿主执行业务判断。例如“选择即允许”可以直接通过，也可以先等待业务接口确认；这与按资源 ID 拉取问题数据是两回事。
5. 业务允许后，宿主把收到的 `event.revealKey` 加入列表，再将新列表传给渲染器，此时为 `["report-access"]`。
6. 渲染器重新计算可见内容并显示后续段落。等待框架完成渲染与布局后，再滚动到 `option-a`。
7. 如需重新隐藏，宿主从列表移除 `report-access`，渲染器重新计算即可。

核心规则：**点击选项只通知业务和请求定位，不由渲染器擅自解锁；宿主更新 revealedKeys 才代表允许显示。** 即使选项没有绑定目标，宿主仍可按业务规则解锁，只是不执行跳转。

宿主更新列表的框架无关写法如下；它应放在“业务允许，且请求仍属于当前文章/有效交互”的分支内：

```js
const nextRevealedKeys = [...new Set([...revealedKeys, event.revealKey])];
// 通过宿主框架的状态更新机制，将 nextRevealedKeys 传给渲染器。
```

若解锁由外部按钮触发而非选项点击，宿主也可从当前 JSON 的问题节点读取 revealKey，业务允许后加入列表，无需知道它的生成规则。

### 3.3 能不能使用固定值？

可以。在编辑器右侧手动将 revealKey 改成约定值，例如 `article-content`。当前编辑器默认仍是自动生成值，本文不改变该默认行为。

| 使用情况 | 配置与行为 |
| --- | --- |
| 每篇文章仅一个问题模块，需要统一解锁约定 | 不同文章都可设为 `article-content`；宿主允许后传 `["article-content"]` |
| 同一篇文章有两个问题模块，分别控制阅读进度 | 分别设为 `step-1`、`step-2`，不能使用同一个值 |
| 希望一次解锁同篇文章的两个模块 | 传入 `["step-1", "step-2"]`，而不是让两个模块使用重复值 |
| 保持编辑器自动生成值 | 从选项事件或当前 JSON 读取，按相同规则解锁 |

固定值与随机值的匹配逻辑完全一样，区别只是宿主如何取得这个值。当前协议要求**所有问题模块**的 revealKey 在同篇文章内唯一，即使某个模块关闭 hideFollowing 也不能重复。

### 3.4 解锁状态属于哪篇文章？

`revealedKeys` 是宿主运行时状态，不是文章 JSON 中的已解锁标记。渲染器不得把用户选择、业务结果或解锁状态回写到文章快照中。

切换文章时默认清空解锁列表和待跳转任务；如需保存阅读进度，应由宿主按用户、文章及版本隔离存储并确认是否恢复。尤其不能将全局 `["article-content"]` 直接传给所有文章，否则使用相同固定值的文章会一起显示后续内容。

异步业务请求要关联当前文章实例/版本和交互序号。旧文章、已取消或已被新选择替代的请求返回时，应忽略其结果，不能解锁新文章。可使用宿主已有文章 ID 加加载代次识别上下文；这不是要求向 ProseMirror JSON 增加 articleId 字段。

## 4. 隐藏范围与计算方式

### 4.1 由独立渲染器负责，不靠编辑器样式

从原始文档顶层节点按顺序扫描：先保留当前节点，再判断它是否为尚未解锁的隐藏边界。如果是，停止扫描。因此问题自身仍显示，问题之后的全部内容暂不创建 DOM；前面的内容不受影响。

不依赖编辑器 CSS 类、不使用编辑器的提示文案，也不通过修改原始 JSON 删除后续节点。编辑器中的“已配置隐藏后续内容”“此文字不会显示在最终渲染上，只在编辑器内提示”和配置按钮都不属于文章展示数据，最终渲染器无需输出。

下面是独立于框架的参考计算函数，前提是文档已通过第 6 节校验：

```js
function getVisibleContent(document, revealedKeys = []) {
  const allowed = new Set(revealedKeys);
  const visible = [];

  for (const node of document.content ?? []) {
    visible.push(node);

    if (
      node.type === 'resourceQuestion' &&
      node.attrs.hideFollowing === true &&
      !allowed.has(node.attrs.revealKey)
    ) {
      break;
    }
  }

  return visible;
}
```

每次 document 或 revealedKeys 变化，都从**原始完整文档**重新计算；不能用上一次截取的可见内容作为输入，否则解锁后无法找回后续节点。返回的节点仅供读取，不修改其属性。

### 4.2 多个隐藏模块的例子

假设文章顺序为：引言 → 问题 A → 段落 A → 问题 B → 段落 B。两个问题都开启 hideFollowing，revealKey 分别为 `step-1`、`step-2`。

| revealedKeys | 可见内容 |
| --- | --- |
| `[]` | 引言、问题 A |
| `["step-1"]` | 引言、问题 A、段落 A、问题 B |
| `["step-2"]` | 引言、问题 A；后面的解锁不能绕过前面的未解锁边界 |
| `["step-1", "step-2"]` | 全文 |
| `["unknown"]` | 引言、问题 A；未知值不产生解锁效果 |

移除已有解锁值后再次按顺序计算。hideFollowing 为 false 的问题永不截断内容。没有隐藏模块的旧文章完整显示。移动问题模块会改变隐藏边界，因为范围由文档顺序决定，而不是按 targetAnchorId 划分。

## 5. 选项跳转段落的实现计划

### 5.1 建立锚点映射

1. 遍历完整文档中所有 paragraph/heading，包括列表、引用、表格内的段落，收集 `attrs.anchorId`，用于判断目标是否存在。
2. 渲染可见段落或标题时，在当前渲染器实例内注册 `anchorId → DOM 元素`，卸载节点时注销；也可输出 `data-anchor-id` 辅助调试。
3. 根据当前问题实例 ID 找到该问题，再按稳定的选项 ID 读取 `targetAnchorId`。不按选项文案、数组下标或段落序号绑定。

推荐使用实例内注册表。不要全局调用 document.getElementById，也不要把未经转义的 ID 拼进 CSS 选择器。两篇文章允许使用同样的锚点字符串，定位必须限制在当前文章容器内。

### 5.2 处理点击与延迟定位

所有有效选项点击都发出第 3 节的事件，宿主自行决定业务处理。定位按以下分支执行：

| 目标状态 | 渲染器行为 |
| --- | --- |
| 选项未设置 targetAnchorId | 不跳转；不妨碍宿主处理选项事件 |
| 目标不在完整文档中 | 提示绑定目标已失效，不按文字猜测、不盲目重试 |
| 目标已渲染且可见 | 滚动当前内容容器，可短暂高亮目标 |
| 目标在完整文档中，但被隐藏 | 记录最新待定位目标；等待宿主解锁，不自动修改 revealedKeys |

为避免宿主同步解锁时漏掉定位，先记录待定位状态，再发出选项事件。解锁列表变化后执行“重新计算可见内容 → 框架提交 DOM → 等待布局 → 查找可见目标 → 滚动”，不要在更新状态后立刻查询尚未生成的 DOM。

若目标仍被后面的另一个未解锁问题阻挡，保留当前有效待定位任务或明确提示仍需解锁；不得为了跳转而自动解锁其余模块。目标一旦定位成功就清除任务，避免每次重渲染都重复滚动。

### 5.3 取消与布局细节

- 新的选项点击替换旧任务；文章替换或卸载时清除任务。
- 建议提供运行时 `cancelPendingNavigation()` 方法，供宿主在业务拒绝、失败、取消或主动重新锁定时调用。该方法也属于待实现的渲染器接口，不是现有编辑器 API。
- 框架渲染完成后再读取目标位置；图片应尽量预留尺寸，防止加载导致目标偏移。不要用无限轮询等待不存在的节点。
- 支持宿主的内容滚动容器和顶部遮挡偏移；高亮只改变 UI，不改变 JSON。
- 可聚焦目标或发送无障碍提示，让键盘用户知道跳转结果；尊重减少动态效果的系统偏好。

## 6. 校验、兼容与安全

先使用下载协议里的 `documentSchema` 校验结构，再执行 `resourceQuestionRules.identity` 中的身份唯一性约束（见第 2 节）。这些跨节点约束不能只依赖 JSON Schema 的 `uniqueItems` 实现。已有 Vue 宿主可复用编辑器包的 `validateProtocolDocument`；其他框架可以按协议独立实现，不必为此引入编辑器运行时。

- 重复问题 ID、重复 revealKey、重复 anchorId 或问题内重复选项 ID：明确报错，不随意选择第一个匹配项。
- resourceId、title、description 都为空字符串且 options 为空数组：是合法的未配置占位，显示中性占位，不伪造答案或自动解锁；如其 hideFollowing 为 true，仍按正常隐藏规则处理，解锁只能由宿主决定。
- targetAnchorId 指向已删除段落：是可修复的绑定警告，不丢弃整篇文章，禁止猜测目标。
- 问题名、描述、选项文案均为纯文本：使用框架文本插值或 DOM textContent，不作为 HTML 注入。
- 用户选择和解锁状态仅保存在运行时；不修改快照，不调用资源接口获取新问题数据。

**隐藏是展示规则，不是授权机制。** 即使不创建隐藏内容的 DOM，完整文章仍在客户端 JSON 中，用户可以读取。付费、隐私等敏感内容应由服务器鉴权后才返回。revealKey 是公开标识，不能当作密码、安全令牌或业务鉴权结果。

## 7. 渲染器验收清单

- [ ] 旧版文章、无问题模块或全部关闭 hideFollowing 时，正常显示全文。
- [ ] 根据保存快照展示问题，不请求资源接口；外部数据修改不影响已保存文章。
- [ ] 有 image 时等比例显示在标题上方，无 image 时不留空白；加载失败不阻断选项。大图缩放不裁切、不产生固定高度留白。
- [ ] 初始 revealedKeys 为空时，显示到首个未解锁问题（含问题自身）。
- [ ] 选项事件携带正确的问题、资源、选项、解锁标识及可选目标；相同文案的不同选项仍能区分。
- [ ] 点击选项不会自行解锁；宿主传入匹配值才显示，移除匹配值后重新隐藏。
- [ ] 自动生成值和手动固定值使用相同的精确匹配规则；未知值无效。
- [ ] 多隐藏模块符合第 4.2 节所有情况，后面的解锁不绕过前面的未解锁模块。
- [ ] 可见目标直接定位；隐藏目标在业务允许且 DOM 就绪后定位；缺失/未绑定目标不错误跳转。
- [ ] 新绑定的 option.id 可定位到同名 data-anchor-id；旧版 targetAnchorId 与 option.id 不一致时仍正确定位，不自动改写文章。
- [ ] 异步失败、取消、连续点击、切换文章和卸载不会产生迟到解锁或错误滚动。
- [ ] 多实例和同名固定 revealKey 的不同文章互不影响；切换文章不继承未明确恢复的解锁状态。
- [ ] 重复身份报错、合法占位正常显示、纯文本被正确转义。
- [ ] 全流程不修改原始 JSON，不显示编辑器专用提示或配置按钮。
